# Document coverage

Infer the structure from the subject, adopters, authority, evidence, and requested output format. Use the following as a coverage probe, not a mandatory table of contents:

- purpose and problem;
- scope and non-goals;
- intended adopters, actors, or situations;
- accepted terminology;
- shared semantic model or principles;
- normative expectations, behavior, interactions, formats, or practices;
- legitimate variation, extensions, or profiles;
- failures, exceptions, and edge cases;
- adoption or evaluation method appropriate to the subject;
- limitations, unresolved areas, and reassessment triggers;
- version and maintenance information;
- evidence and decision references useful to maintainers.

Omit irrelevant material, rename sections in domain language, and add subject-specific coverage. Start in one primary document. Split into indexed modules only when independent concerns, reuse, or document size makes navigation materially better.

Use normative keywords only when their defined strength helps the intended readers. Define the keywords or cite the governing convention. Keep examples distinguishable from requirements.

The published artifact must remain understandable without opening the tracker.
